# Parqon website + CMS

The site is a Next.js app with [Payload CMS](https://payloadcms.com) built in. The website and the admin
panel (`/admin`) are one project and one deployment.

## What the CMS manages

| Section | Where |
|---|---|
| Products (images, gallery, specs, finishes, show/hide) | Catalogue → Products |
| Categories and their types (card images, show/hide, order) | Catalogue → Categories |
| Brochures (cover, PDF, show/hide) | Content → Brochures |
| Certification logos (which brands show them, order) | Content → Certifications |
| Addresses, e-mails, phone, WhatsApp hours, social links | Content → Contact details |
| Show/hide the Brochures page and buttons | Settings → Site settings |
| Quote / sample / brochure / contact requests | Leads → Leads |
| Uploaded files, users | Settings → Media / Users |

Changes show on the website straight away (pages read the CMS on every request).
Editors can add and change content; only admins can delete or manage users. The first account created becomes the admin.

Leads are saved under **Leads** and e-mailed through the existing AWS Lambda endpoint (`LEAD_ENDPOINT`).

## Running it locally

Needs Node **22.23.4+** or **24.22.1+**.

```bash
npm install
cp .env.example .env        # set PAYLOAD_SECRET (any long random string)
npm run seed                # first time only: imports the current products, categories, etc.
npm run dev                 # http://localhost:3000 and http://localhost:3000/admin
```

Without `DATABASE_URL` it uses a local SQLite file (`parqon.db`); without `S3_BUCKET` uploads are stored in `./media`.
Both are git-ignored.

## Going live (Vercel)

Vercel's file system doesn't keep files, so production needs a database and file storage:

1. **Database**: create a Postgres database (e.g. Neon from the Vercel Marketplace) and set `DATABASE_URL`.
2. **Uploads**: create an S3 bucket (optionally behind the existing CloudFront) and set
   `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (and `S3_PUBLIC_URL` for CloudFront).
3. Set `PAYLOAD_SECRET`, `LEAD_ENDPOINT` and `NEXT_PUBLIC_SITE_URL` in the Vercel project.
4. With those set locally too, create the database tables and import the content once:
   ```bash
   npm run payload migrate:create initial
   npm run payload migrate
   npm run seed
   ```
   Commit the generated `src/migrations` folder; run `npm run payload migrate` again after future schema changes.
5. Deploy. Then open `/admin` and create the first (admin) account.

## Code map

- `src/app/(frontend)` – website routes; `src/app/(payload)` – admin panel and API (generated by Payload)
- `src/collections`, `src/globals` – CMS content types; `src/payload.config.ts` – CMS setup
- `src/lib/catalog` – loads CMS content for the site (`server.ts`) and shares it with components (`context.tsx`)
- `src/lib/leads.ts` – saves and e-mails form submissions
- `src/lib/router.tsx` – the small router API the components use, on top of Next.js navigation
- `src/views`, `src/components` – the site's pages and components
- `src/seed` – one-off import of the old static content (`legacy/`) into the CMS
